## Current lifecycle dependencies

1. **Order:** published → accepted → in_progress → completion_requested → completed; cancellation is allowed from published/accepted. A dispute can move a live order to disputed and stores pre_dispute_status.
2. **Proposal:** worker submits once; client acceptance atomically claims published order, assigns worker, accepts chosen proposal, rejects remaining proposals.
3. **Payment:** client wallet debit → payment held → release to worker/platform on completion or refund to client on cancellation/dispute.
4. **Withdrawal:** wallet bucket move available→processing happens before insertion; cancellation moves it back. This ordering needs a single PostgreSQL transaction.
5. **Identity:** registration, Google sign-in/linking, email/phone verification, password reset and token-version revocation all depend on users/auth_accounts/verification_tokens/security_events.
6. **Admin:** permissions are enforced by the backend, not the client. Admin actions and financial/dispute actions must be transactional and auditable.
7. **Webhook:** HMAC signature then event-id deduplication. PostgreSQL must persist raw payload, signature result, processing state and provider/event unique key.

## Required code changes before PostgreSQL write cutover

- Replace direct Motor collection calls with repository/service implementations selected by a database feature flag. Do not dual-write financial records until a reconciliation design is approved.
- Use `Decimal`/integer cents at HTTP boundaries; current Pydantic float fields and Mongo deposits/withdrawals/orders/proposals can round differently.
- Move base64 blobs to private object storage and migrate references, not blob content, to PostgreSQL.
- Add status-history writes and outbox/webhook processing in the same transaction as each state change.
- Encrypt bank details with envelope encryption/KMS and enforce least-privilege decryption.
- Add FK validation for each legacy reference; invalid references go to a quarantine report and block cutover, not silently to NULL.
